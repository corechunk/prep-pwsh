# 📂 File 07 — Layout Panels Deep Dive (Grid, StackPanel, DockPanel, WrapPanel, Canvas, Splitters)

---

# THEORY

WPF layout is one of its strongest systems.

Every visual element is placed inside a layout container.

The container decides:

- How children are sized
- How children are positioned
- How resizing behaves
- Whether layout is responsive

Core layout panels:

- Grid (most powerful, responsive)
- StackPanel (vertical/horizontal stacking)
- DockPanel (dock to edges)
- WrapPanel (auto wrap like flow layout)
- Canvas (absolute positioning)
- UniformGrid (even distribution)
- Viewbox (scaling container)
- GridSplitter (resizable panels)

Layout engine uses a two-pass system:

1. Measure
2. Arrange

Understanding layout = understanding responsive WPF UI.

All examples compatible with:

- PowerShell 5.1
- PowerShell 7.1 (Windows)

---

# SECTION 1 — GRID (PRIMARY LAYOUT SYSTEM)

Grid is the most important layout container.

Supports:

- Rows
- Columns
- Star sizing
- Auto sizing
- Spanning
- Nested grids

---

## Example: Basic Grid

```xml
<Grid>
    <Grid.RowDefinitions>
        <RowDefinition Height="50"/>
        <RowDefinition Height="*"/>
    </Grid.RowDefinitions>

    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="200"/>
        <ColumnDefinition Width="*"/>
    </Grid.ColumnDefinitions>

    <Button Content="Top Left" Grid.Row="0" Grid.Column="0"/>
    <Button Content="Bottom Right" Grid.Row="1" Grid.Column="1"/>
</Grid>
```

---

## Row / Column Sizing Types

Height / Width options:

- Fixed: 100
- Auto: content-based
- Star: remaining space (*)

Examples:

```xml
<RowDefinition Height="Auto"/>
<RowDefinition Height="*"/>
<RowDefinition Height="2*"/>
```

Star sizing distributes remaining space proportionally.

---

## Spanning Cells

```xml
<Button Content="Span 2 Columns"
        Grid.ColumnSpan="2"/>
```

---

# SECTION 2 — STACKPANEL

Stacks items in one direction.

Orientation:

- Vertical (default)
- Horizontal

---

## Example

```xml
<StackPanel Orientation="Vertical">
    <Button Content="Button 1"/>
    <Button Content="Button 2"/>
    <Button Content="Button 3"/>
</StackPanel>
```

Important note:

StackPanel does NOT constrain children size in stacking direction.

---

# SECTION 3 — DOCKPANEL

Docks elements to edges.

Order matters.

```xml
<DockPanel>
    <Button Content="Top" DockPanel.Dock="Top"/>
    <Button Content="Left" DockPanel.Dock="Left"/>
    <Button Content="Right" DockPanel.Dock="Right"/>
    <Button Content="Bottom" DockPanel.Dock="Bottom"/>
    <Button Content="Fill"/>
</DockPanel>
```

Last child fills remaining space.

---

# SECTION 4 — WRAPPANEL

Auto-wrap container.

Useful for:

- Dynamic button lists
- Tag clouds
- Responsive icon grids

```xml
<WrapPanel Orientation="Horizontal">
    <Button Content="Item 1"/>
    <Button Content="Item 2"/>
    <Button Content="Item 3"/>
</WrapPanel>
```

Automatically wraps when width exceeded.

---

# SECTION 5 — CANVAS (ABSOLUTE POSITIONING)

Positions by coordinates.

```xml
<Canvas>
    <Button Content="Move Me"
            Canvas.Left="100"
            Canvas.Top="50"/>
</Canvas>
```

Runtime move:

```pwsh
[System.Windows.Controls.Canvas]::SetLeft($btn, 200)
[System.Windows.Controls.Canvas]::SetTop($btn, 150)
```

Use for:

- Drag systems
- Custom drawing
- Overlay UI

Not responsive by default.

---

# SECTION 6 — UNIFORMGRID

Evenly distributes space.

```xml
<UniformGrid Rows="2" Columns="3">
    <Button Content="1"/>
    <Button Content="2"/>
    <Button Content="3"/>
    <Button Content="4"/>
    <Button Content="5"/>
    <Button Content="6"/>
</UniformGrid>
```

All cells equal size.

---

# SECTION 7 — VIEWBOX (SCALING CONTAINER)

Scales content automatically.

```xml
<Viewbox Stretch="Uniform">
    <TextBlock Text="Scalable Text" FontSize="40"/>
</Viewbox>
```

Used for DPI scaling or zooming UI.

---

# SECTION 8 — GRID SPLITTER (RESIZABLE PANELS)

YES — you CAN create sliding width panels.

This is native in WPF.

---

## Example: Resizable Sidebar

```xml
<Grid>
    <Grid.ColumnDefinitions>
        <ColumnDefinition Width="200"/>
        <ColumnDefinition Width="5"/>
        <ColumnDefinition Width="*"/>
    </Grid.ColumnDefinitions>

    <Border Background="#EEE" Grid.Column="0">
        <TextBlock Text="Sidebar"/>
    </Border>

    <GridSplitter Grid.Column="1"
                  Width="5"
                  HorizontalAlignment="Stretch"
                  VerticalAlignment="Stretch"
                  Background="Gray"
                  ShowsPreview="True"/>

    <Border Background="White" Grid.Column="2">
        <TextBlock Text="Main Content"/>
    </Border>
</Grid>
```

User can drag splitter to resize width.

No manual mouse handling required.

---

# SECTION 9 — MANUAL SLIDING PANEL (MOUSE DRAG WIDTH)

If you want full custom behavior:

```pwsh
$splitter.Add_MouseMove({
    if ($_.LeftButton -eq "Pressed") {
        $pos = $_.GetPosition($window)
        $grid.ColumnDefinitions[0].Width =
            New-Object System.Windows.GridLength($pos.X)
    }
})
```

But GridSplitter is preferred.

---

# SECTION 10 — RESPONSIVE LAYOUT STRATEGY

Best practice:

- Outer Grid
- Top = Auto
- Bottom = *
- Sidebar fixed or star
- Main area star
- Nested grids inside sections

Avoid:

- Overusing Canvas
- Fixed pixel layouts everywhere

# SECTION 11 — DYNAMICALLY ADDING CONTROLS

```pwsh
$btn = New-Object System.Windows.Controls.Button
$btn.Content = "Dynamic"

$panel.Children.Add($btn)
```

Remove:

```pwsh
$panel.Children.Remove($btn)
```

Clear:

```pwsh
$panel.Children.Clear()
```

# SECTION 13 — NESTED LAYOUT PATTERN (REAL WORLD)

Common structure:

```text
Window
 └ Grid
    ├ Row 0 → Header (Auto)
    ├ Row 1 → Content (*)
    │    └ Grid
    │       ├ Column 0 → Sidebar (Auto)
    │       ├ Column 1 → Splitter
    │       └ Column 2 → Main (*)
    └ Row 2 → Footer (Auto)
```
This creates full professional app layout.

---

# SECTION 14 — PERFORMANCE NOTES

Grid = most flexible
StackPanel = simple stacks
Canvas = manual control
WrapPanel = auto flow
UniformGrid = equal distribution

Over-nesting too many panels can affect performance slightly in large apps.
