# 📂 File 08 — Advanced Event Handling in WPF + PowerShell

---

# THEORY

WPF events are powerful and flexible. They are categorized mainly as:

1. **Direct events** – Fired only on the element (like Click on Button)
2. **Bubbling events** – Travel up the visual tree (MouseDown, KeyDown)
3. **Tunneling events** – Travel down the visual tree (PreviewMouseDown)
4. **Routed events** – Can be handled anywhere in the tree
5. **Custom events** – User-defined events for custom controls

Key points:

- All events are delegates under the hood.
- `Add_Click` is a simplified syntax in PowerShell.
- You can attach multiple handlers to the same event.
- You can remove handlers with `Remove_Click`.
- You can handle events dynamically at runtime.

# SECTION 1 — BUTTON EVENTS

Common events:

- Click
- MouseEnter / MouseLeave
- MouseMove / MouseDown / MouseUp
- PreviewMouseDown (tunnel)
- PreviewMouseUp
- KeyDown / KeyUp (if focused)
- GotFocus / LostFocus

---

## Example: Basic Click

```pwsh
$btn.Add_Click({
    Write-Host "Button clicked"
})
```

---

## Mouse Enter / Leave

```pwsh
$btn.Add_MouseEnter({
    $btn.Background = "LightBlue"
})

$btn.Add_MouseLeave({
    $btn.Background = "White"
})
```

---

## Mouse Down / Up

```pwsh
$btn.Add_MouseDown({
    Write-Host "Mouse button pressed on button"
})

$btn.Add_MouseUp({
    Write-Host "Mouse button released on button"
})
```

# SECTION 6 — ROUING EVENTS (Bubbling vs Tunneling)

**Bubbling** – event starts at source and goes up the visual tree.

**Tunneling** – event starts at root and goes down to source.

Prefix `Preview` is tunneling:

- PreviewMouseDown
- PreviewKeyDown

---

## Example: Bubbling

```pwsh
$stackPanel.Add_PreviewMouseDown({
    Write-Host "StackPanel detected a mouse down (tunnel)"
})

$stackPanel.Add_MouseDown({
    Write-Host "StackPanel detected a mouse down (bubble)"
})
```

# SECTION 9 — CUSTOM EVENTS

1. Define a script block
2. Expose via `.Add_MyCustomEvent` or manual delegate
3. Raise with `$element.RaiseEvent($args)`

Example:

```pwsh
# Define delegate type
$myEvent = [System.Windows.RoutedEventHandler]{
    param($sender, $args)
    Write-Host "Custom event triggered"
}

# Add event
$btn.Add_Click($myEvent)
```

---

# SECTION 10 — DYNAMIC EVENT ATTACHMENT

Attach events dynamically based on name:

```pwsh
function Attach-Event($element, $eventName, $scriptBlock) {
    $event = $element.GetType().GetEvent($eventName)
    $handler = [System.Delegate]::CreateDelegate($event.EventHandlerType, $scriptBlock.Target, $scriptBlock.Method)
    $event.AddEventHandler($element, $handler)
}

Attach-Event $btn "Click" { Write-Host "Dynamic Click" }
```

# SECTION 12 — BEST PRACTICES

- Always use Add_XXX / Remove_XXX in PowerShell.
- Use tunneling (`Preview`) for intercepting events before children.
- Use bubbling when you want parent to react to child events.
- Use scriptblocks for modular, reusable handlers.
- For dynamic UI, attach events immediately after control creation.

---

# SECTION 13 — DYNAMIC HANDLER FOR MULTIPLE CONTROLS

```pwsh
    $btn.Add_Click({
        Write-Host "Clicked: $($btn.Content)"

```

# SECTION 14 — VISUAL FEEDBACK ON EVENTS

Change color, border, text dynamically:

```pwsh
$btn.Add_MouseEnter({ $btn.Background = "Yellow" })
$btn.Add_MouseLeave({ $btn.Background = "Gray" })
$btn.Add_Click({ $btn.Content = "Clicked!" })
```

---

# SECTION 15 — LIFECYCLE HOOKS

- Loaded → after all children created
- Unloaded → when removed from visual tree
- Initialized → during object creation

```pwsh
$window.Add_Initialized({ Write-Host "Window object created" })
$window.Add_Loaded({ Write-Host "Window fully loaded" })
$window.Add_Unloaded({ Write-Host "Window removed from tree" })
```
